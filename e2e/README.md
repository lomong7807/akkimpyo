# e2e — 끝에서 끝까지 테스트

Playwright로 web 화면을 실제 브라우저에서 돌린다. 무엇을 여기에 두는지는 [테스트 전략](../docs/qa/test-strategy.md)을 따른다.
핵심 흐름만 두고, 계산과 분기는 아래 층(`web/tests/`, `server/`)에서 본다.

| 프로젝트 이름 | 브라우저 | 화면 |
|---|---|---|
| `chromium` | Chromium (`Desktop Chrome`) | 1280×720. 넓은 화면(화면설계서 00-common 2.5, 1024px 이상) |
| `webkit-iphone` | WebKit (`iPhone 17`) | 402×681, 터치. Safari와 같은 엔진이지만 실제 아이폰은 아니다 |

## 실행

전제: `web/`에서 `npm ci`를 먼저 해 둔다. 테스트가 web의 개발 서버를 띄우기 때문이다.

아래 명령은 `e2e/`에서 실행한다. 2026-11-26에 macOS(arm64), Node 24.3.0 / npm 11.4.2에서 실행해 확인했다.

| 할 일 | 명령 |
|---|---|
| 설치 | `npm ci` |
| 브라우저 설치 (처음 한 번, Playwright 버전을 올린 뒤에도) | `npx playwright install chromium webkit` |
| 전체 실행 (두 브라우저) | `npm test` |
| 한 브라우저만 | `npx playwright test --project=chromium` 또는 `npx playwright test --project=webkit-iphone` |

- 테스트를 시작하면 `playwright.config.ts`의 `webServer`가 web 개발 서버를 포트 **5180**으로 띄우고, 끝나면 끈다.
  개발할 때 쓰는 5173과 겹치지 않게 했다. 5180을 이미 다른 프로세스가 쓰고 있으면 이어 쓰지 않고 실패한다.
- 서버(`server/`)는 띄우지 않는다. 개발 서버가 `/api`를 8080으로 넘기려다 닿지 못해
  `[WebServer] ... http proxy error: /api/v1/auth/refresh ... ECONNREFUSED`가 찍힌다. 지금 테스트에서는 정상이다.
- 재시도는 0이다. 실패하면 다시 돌려서 덮지 말고 원인을 본다. 실패한 테스트의 기록(trace)은 `test-results/`에 남고,
  그것을 여는 명령은 실패 출력에 함께 찍힌다.

## 쓰는 규칙

- 요소는 사용자가 보는 것으로 찾는다: `getByRole` → `getByLabel` → `getByText` 순서이고 `getByTestId`는 마지막이다.
  role로 찾지 못하면 테스트를 우회하지 말고 접근성 결함으로 보고한다.
- 기대 동작은 화면설계서(`docs/planning/05-screen-spec/`)와 기능정의서에서 가져오고, 테스트에 근거 위치를 적는다.
  화면이 다르게 동작하면 테스트를 화면에 맞추지 말고 버그로 보고한다.
- 테스트마다 데이터를 따로 쓰고, 다른 테스트의 결과에 기대지 않는다.
- 고정 대기(`waitForTimeout`)를 쓰지 않는다. 기다림은 `expect`의 자동 재시도에 맡긴다.
- 서버 응답이 필요한 흐름을 `page.route`로 흉내 내지 않는다. 서버 API가 생긴 뒤에 실제 서버로 넣는다.

## 서버 API가 생기면 더할 것

[테스트 전략](../docs/qa/test-strategy.md) 3절의 핵심 흐름 4개를 더한다. 테스트마다 새 이메일로 가입해 장부를 따로 쓴다(같은 문서 4절).

1. 가입 → 첫 계좌 만들기 → 지출 입력 → 내역에 보임 → 홈의 이번 달 합계와 계좌 잔액이 맞음
2. 로그아웃 → 로그인 → 같은 데이터가 보임
3. 거래 수정 → 삭제 → 되돌리기 뒤 합계가 원래대로 돌아옴
4. 수입·이체 입력 뒤 잔액이 맞고, 이체가 수입·지출 합계에 들어가지 않음

서버가 "로그인 필요"라고 답해야 볼 수 있어 지금은 넣지 않은 것도 그때 함께 본다.
서버가 없으면 이 화면들은 로그인 여부를 확인하지 못한 화면("불러오지 못했어요.", 00-common 4.1)으로 열린다.

- 로그인 없이 보호된 주소(`/home`, `/transactions/new`)를 열면 로그인으로 간다(F-011, 00-common 4.1)
- 로그인 없이 없는 주소를 열면 로그인으로 가고, 로그인 뒤에는 찾을 수 없음(N-01)이 보인다(01-auth-home-settings.md N-01)
- 휴대폰 폭에서 하단 탭, 넓은 화면에서 사이드바가 보인다(B-01, 00-common 2.5와 6.2)
