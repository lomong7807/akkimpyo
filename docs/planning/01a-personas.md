# 페르소나와 사용 케이스

- 작성일: 2026-11-18
- 상태: 초안, 사용자 확인 전
- 배경: 사용자가 "페르소나를 더 추가해서 더 다양한 케이스를 생각하라"고 요청해 만든 문서이다. `[사용자]`
- 모든 페르소나는 `[제안]`이며 실제 인터뷰가 아니라 설계자가 가정한 인물이다.
- 근거 문서: [프로젝트 개요서](01-project-overview.md), [설계 문서](../superpowers/specs/2026-11-18-account-book-design.md)
- 표기: `[사용자]` 사용자가 직접 정함, `[제안]` 설계자가 제안했고 사용자 확인 전, `[사실]` 조사로 확인
- 케이스 표시: "다룸(어디서)"은 현재 설계가 이미 다루는 경우, "빈틈(G-번호)"은 3절 목록에 올린 경우이다. "IA 빈틈 N"은 IA 문서의 빈틈 번호이다.

## 2. 페르소나별 상세

### P1 김도윤, 33세, 직장인, 혼자 씀 (핵심) `[제안]`

- 상황: 회사에서는 맥북, 밖에서는 아이폰을 쓴다.
- 행동 패턴: 결제 직후 적으려다 미루고 주말에 몰아서 입력한다. 가계부 앱을 두 번 그만뒀다.
- 페인 포인트: 입력이 귀찮다. 기기 간 동기화가 유료다. 여행 지출이 월 통계를 흐린다.

이 사람이 드러내는 케이스:

- C-01 지하철처럼 연결이 끊긴 곳에서 입력한다. 현재 설계: 다룸(오프라인 입력, 보내지 않은 입력 표시)
- C-02 주말에 일주일 치를 몰아서 넣는다. 결제 시각을 모른다. 현재 설계: 다룸(시각 없는 거래는 날짜로 이벤트 판정). 여러 건을 연달아 빠르게 넣는 흐름은 한 줄 입력으로 다룬다.
- C-03 맥북에서 고치는 중에 아이폰에서 같은 거래를 고친다. 현재 설계: 다룸(수정 충돌 안내)
- C-04 여행 중 넷플릭스 정기결제가 나간다. 현재 설계: 다룸(반복 거래는 이벤트에서 기본 제외, 수동 제외)
- C-05 해외여행에서 외화로 결제한다. 현재 설계: 범위 밖(다중 통화). 원화로 환산해 직접 적는다.
- C-06 여행지 시간대가 장부 시간대와 다르다. 현재 설계: 빈틈(G-23)

### P2 이서연, 31세, 맞벌이 신혼 (핵심) `[제안]`

- 상황: 배우자와 한 계정에 같이 로그인해 살림 가계부를 쓴다.
- 행동 패턴: 데이트 비용과 모임 회비는 엑셀로 따로 관리한다.
- 페인 포인트: 누가 쓴 지출인지 구분되지 않는다. 살림·모임·개인 지출이 섞인다. 내 지출만 따로 보기 어렵다.

이 사람이 드러내는 케이스:

- C-07 개인 장부를 배우자와 통째로 공유한다. 현재 설계: 다룸(개인 장부에 초대)
- C-08 배우자와 같은 지출을 둘 다 입력한다. 현재 설계: 다룸(같은 금액·가맹점이 몇 분 안에 있으면 경고). 경고 범위가 다른 구성원의 입력에도 적용되는지는 기능정의서에서 명시해야 한다. 빈틈(G-26)
- C-09 배우자에게 보이고 싶지 않은 지출(선물)이 있다. 현재 설계: 다룸(개인 장부를 따로 두면 됨). 단 개인 장부를 통째로 공유한 경우에는 혼자만 보는 장부가 없어진다. 빈틈(G-27)
- C-10 공동 생활비 통장으로 각자 이체한다. 현재 설계: 다룸(이체는 수입·지출 합계에서 제외)
- C-11 내 지출만 모아 본다. 현재 설계: 다룸(내 전체 지출)

### P3 박준호(29세)와 최하은(28세), 연애 중인 커플 `[제안]`

- 상황: 데이트 통장을 같이 쓰고 데이트 장부를 따로 만들었다.
- 행동 패턴: 매주 주말 데이트를 이벤트로 묶고 싶어 한다. 각자 카드로 결제할 때도 있다.
- 페인 포인트: 데이트 비용만 따로 보고 싶다. 누가 더 냈는지 알고 싶다.

이 사람이 드러내는 케이스:

- C-12 각자 카드로 결제한다. 현재 설계: 다룸(결제한 사람별 합계). 누가 누구에게 얼마 줘야 하는지는 범위 밖(정산)이다.
- C-13 매주 데이트마다 이벤트를 새로 만드는 것이 번거롭다. 현재 설계: 빈틈(G-21)
- C-14 헤어져서 한 명이 장부를 나간다. 나간 사람도 기록 사본을 갖고 싶다. 현재 설계: 빈틈(G-24). 나간 사람이 적은 거래가 장부에 남는 것은 다룸이다.
- C-15 소유자가 헤어진 뒤 상대를 내보낸다. 현재 설계: 다룸(구성원 내보내기). 내보내진 사람의 열려 있던 화면은 IA 빈틈 9이다.

### P4 정민서, 35세, 친구 여행 모임 총무 `[제안]`

- 상황: 6명이 매달 회비를 내는 여행 모임의 총무이다. 회비 입금과 지출을 기록하고 구성원에게 보여 줘야 한다.
- 행동 패턴: 구성원 대부분은 보기만 한다.
- 페인 포인트: 엑셀을 캡처해 단체방에 올린다. 총무가 바뀌면 인수인계가 어렵다.

이 사람이 드러내는 케이스:

- C-16 구성원 대부분은 보기만 하면 된다. 실수로 고치는 것을 막고 싶다. 현재 설계: 빈틈(G-16). 현재 설계는 구성원 모두 편집 가능하다.
- C-17 가입하기 싫어하는 구성원에게도 보여 주고 싶다. 현재 설계: 빈틈(G-17). 현재 설계는 초대받은 사람도 계정이 필요하다.
- C-18 총무가 바뀐다. 현재 설계: 빈틈(IA 빈틈 4, 소유권 넘기기)
- C-19 회비 입금을 구성원별로 기록한다. 현재 설계: 다룸(수입 거래와 결제한 사람). 누가 이번 달 회비를 안 냈는지 보는 화면은 없다. 범위 밖으로 권고하며 G-17과 함께 사용자 확인이 필요하다.
- C-20 모임 여행 3박 4일을 이벤트로 묶는다. 현재 설계: 다룸(이벤트)

### P5 한지우, 27세, 프리랜서 디자이너 `[제안]`

- 상황: 수입이 불규칙하고 한 달에 여러 건 들어온다. 사업 경비와 개인 지출을 나누고 싶다.
- 행동 패턴: 5월 종합소득세 신고 때 경비 내역이 필요하다.
- 페인 포인트: 월 단위 통계로는 수입이 들쭉날쭉해 의미가 없다. 경비만 뽑기 어렵다.

이 사람이 드러내는 케이스:

- C-21 혼자서 장부를 두 개(개인, 사업) 쓴다. 현재 설계: 다룸(장부 여러 개는 혼자서도 만들 수 있음)
- C-22 연 단위나 임의 기간으로 합계를 본다. 현재 설계: 빈틈(G-18). 현재 통계는 월별이다.
- C-23 경비 내역을 엑셀로 내보낸다. 현재 설계: 다룸(엑셀 내보내기). 기간·카테고리를 골라 내보내는지는 기능정의서에서 명시한다.
- C-24 거래처가 입금을 취소하고 다시 보낸다. 현재 설계: 다룸(취소 상태, 변경 이력)

### P6 오세훈, 41세, 외벌이 가장 `[제안]`

- 상황: 대출 이자, 보험, 학원비 같은 고정지출이 많고 카드가 다섯 장이다. 할부가 여러 건 겹쳐 있다.
- 행동 패턴: 배우자는 입력만 하고 통계는 보지 않는다.
- 페인 포인트: 이번 달 쓸 수 있는 돈이 얼마인지 모른다. 카드값이 나갈 때 지출이 두 번 잡히는 것 같다.

이 사람이 드러내는 케이스:

- C-25 카드 대금이 통장에서 빠져나간다. 현재 설계: 다룸(카드 대금은 이체로 처리, 합계 중복 없음)
- C-26 고정지출과 할부가 많다. 현재 설계: 다룸(3단계 반복 거래, 할부)
- C-27 카드 다섯 장의 결제 문자를 자동으로 넣는다. 현재 설계: 다룸(3단계 문자 자동 입력, 카드 식별 문구)
- C-28 이번 달 남은 예산을 본다. 현재 설계: 다룸(3단계 월 예산)
- C-29 배우자는 입력 화면만 쓴다. 현재 설계: 다룸(빠른 입력). 입력만 하는 사람의 첫 화면을 따로 둘 필요는 없다고 판단한다. `[제안]`

### P7 윤가은, 24세, 사회초년생 `[제안]`

- 상황: 아이폰만 쓰고 Mac은 없다. 간편결제와 현금을 많이 쓰고 친구와 더치페이가 잦다. 가계부는 처음이다.
- 페인 포인트: 가입이 번거로우면 안 쓴다. 친구에게 돌려받은 돈을 어떻게 적을지 모른다.

이 사람이 드러내는 케이스:

- C-30 한 명이 결제하고 친구에게 돌려받는다. 현재 설계: 빈틈(G-19). 환불 방식으로 적을 수 있으나 안내가 없다.
- C-31 이메일과 비밀번호 가입이 번거롭다. 현재 설계: 빈틈(G-25, Apple 로그인 등)
- C-32 계좌와 카테고리를 처음에 무엇으로 채울지 모른다. 현재 설계: 빈틈(G-28, 가입 직후 기본 카테고리와 첫 계좌 안내)
- C-33 아이폰 홈 화면에 웹앱을 추가해 쓴다. 현재 설계: 다룸(설계 문서 10.1 검증 항목)

### P8 장영숙, 58세, PC 웹만 사용 `[제안]`

- 상황: 5년 동안 엑셀로 가계부를 써 왔다. 휴대폰보다 데스크톱 브라우저가 편하다.
- 페인 포인트: 그동안 쓴 엑셀을 버리고 싶지 않다. 화면 글씨가 작다.

이 사람이 드러내는 케이스:

- C-34 지난 5년 치 엑셀을 옮기고 싶다. 현재 설계: 빈틈(G-20). 현재는 카드사 엑셀 가져오기만 있다.
- C-35 글씨를 키워 쓴다. 현재 설계: 빈틈(G-22)
- C-36 넓은 화면에서 여러 건을 한꺼번에 고친다. 현재 설계: 다룸(3단계 일괄 수정)

## 3. 빈틈 목록

번호는 IA 문서의 빈틈 1~15에 이어진다. 권고는 모두 `[제안]`이며 사용자 확인 전이다.

| 번호 | 빈틈 | 관련 케이스 | 설계자 권고 |
|------|------|------------|------------|
| G-16 | 보기만 하는 구성원 권한 | C-16 | 출시 범위에 넣는다. 권한이 OWNER, MEMBER, 보기 전용 세 가지가 된다. |
| G-17 | 가입하지 않은 사람에게 보여 주는 열람 링크 | C-17, C-19 | 출시 후로 미룬다. 타인의 금융 기록을 로그인 없이 여는 길이라 신중해야 한다. |
| G-18 | 연 단위와 임의 기간 통계 | C-22 | 연 단위는 1단계에 넣고, 임의 기간은 내역 필터와 검색으로 대신한다. |
| G-19 | 돌려받은 돈 기록 방법 | C-30 | 새 기능 없이 "돌려받음"을 지출 입력의 선택 항목으로 두고 환불과 같은 방식으로 저장한다. |
| G-20 | 일반 엑셀과 다른 가계부의 과거 데이터 가져오기 | C-34 | 3단계 카드사 엑셀 가져오기의 열 맞추기 화면을 일반 엑셀에도 쓸 수 있게 만든다. |
| G-21 | 반복되는 이벤트를 빠르게 만들기 | C-13 | 지난 이벤트 복제(이름 유지, 날짜만 새로)를 2단계에 넣는다. 자동 반복 생성은 출시 후로 미룬다. |
| G-22 | 글자 크기와 접근성 | C-35 | 브라우저와 기기의 글자 크기 설정을 따르도록 만들고 별도 설정 화면은 두지 않는다. |
| G-23 | 장부 시간대와 다른 곳에서 입력할 때 | C-06 | 거래 날짜와 시각은 입력한 그대로(현지 벽시계 기준) 저장하고 이벤트 판정도 그 값으로 한다. 설계 문서의 장부 시간대 규칙과 맞는지 기능정의서에서 확정한다. |
| G-24 | 나가는 사람의 기록 사본 | C-14 | 나가기 확인 화면에서 엑셀 내보내기를 안내한다. |
