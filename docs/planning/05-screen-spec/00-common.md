## 1. 문서 목적과 읽는 법

### 1.1 목적

화면설계서는 개발자가 화면을 만들 때 보는 마지막 기획 문서다. 와이어프레임이 "어디에 무엇이 있는가"를 정했다면, 화면설계서는 각 요소가 어떻게 보이고(시각 규칙), 무엇이라고 쓰고(문구), 누르거나 조건이 바뀔 때 어떻게 움직이는지(동작, 상태, 예외)를 정한다.

이 문서(공통편)는 모든 화면이 따르는 기준과 공통 틀(B 그룹 6개)을 다룬다. 다른 세 파일은 이 문서의 규칙을 기본값으로 삼고, 화면마다 다른 점과 그 화면에서 실제로 보이는 문구를 적는다. 다른 파일이 이 문서를 가리킬 때는 "00-common 4.3"처럼 절 번호를 쓴다.

### 1.3 화면 하나를 적는 순서

1. 제목: `### B-05 보내지 않은 입력 목록 [1]` (IA와 같은 화면 ID, 이름, 단계)
2. 요소 표: `# | 요소 | 디스크립션`. `#`은 와이어프레임 그림의 `(n)`과 같은 번호다. 디스크립션에는 보이는 조건, 모양, 문구, 누를 때의 동작, 관련 F-ID와 P-ID를 적는다.
3. 상태: 불러오는 중, 처리 중, 그 화면에만 있는 상태
4. 예외 처리: 비로그인 상태, 데이터 없음, 네트워크 오류, 입력값 오류의 네 행. 해당하지 않으면 "해당 없음"과 이유를 적는다. 공통 규칙과 같더라도 "공통 규칙 따름"이라고만 쓰지 않고 그 화면에서 실제로 보이는 것을 한 줄로 적는다.
5. 권한별 차이: 소유자, 편집 가능, 보기 전용에서 달라지는 것
6. 넓은 화면 차이: 폭 1024px 이상에서 달라지는 것

### 1.4 번호와 표기

- 와이어프레임에 번호가 없는 세부 요소(탭 하나하나, 펼친 판 안의 줄 등)는 `n-m`으로 적는다. 와이어프레임 요소 `(n)` 안의 m번째 세부라는 뜻이다. `[판단 1]`
- 화면에 보이는 문구는 큰따옴표 안에 그대로 적는다. 바뀌는 값은 중괄호로 적는다. 예: "보내지 않은 입력 {N}건".
- 단계 표기 `[1]` `[2]` `[3]` `[4]` `[출시]`는 IA와 같다. 단계가 오지 않은 요소는 화면에 만들지 않는다.
- `[판단 n]`: 기능정의서와 브리핑이 정하지 않아 이 문서가 정한 세부다. 9절 표의 번호와 같다.
- `[불일치 n]`: 다른 문서와 어긋났던 곳이다. 10절 표의 번호와 같고, 그 표에 2026-11-20 설계자 결정과 반영한 곳을 적었다.
- 권한 이름은 기능정의서 1.3을 따른다. 소유자, 편집 가능, 보기 전용. "편집 이상"은 소유자와 편집 가능이다.

## 2. 시각 방향

앱 화면은 제품 UI다. 목표는 차분하고 숫자가 잘 읽히는 화면이며 장식은 넣지 않는다. 차가운 회색 중립색 한 계열에 강조색(짙은 초록) 하나만 쓴다. 따뜻한 회색, 보라·파랑 그라데이션, 네온, 크림·베이지 배경은 쓰지 않는다. 소개 페이지(A-01)만 랜딩 페이지 규칙을 더 쓰며, 그때도 색과 글꼴은 이 절을 그대로 따른다(01-auth-home-settings.md A-01).

### 2.1 색 토큰

화면은 기본으로 기기 설정(`prefers-color-scheme`)을 따라 밝은 화면과 어두운 화면 중 하나로 보인다. 사용자는 화면 설정(M-03)에서 "시스템 따름"(기본), "밝게", "어둡게"를 골라 수동으로 바꿀 수 있고, 고른 값은 그 기기에만 저장된다(F-902). `[불일치 1]`

아래 색 토큰은 두 경로 모두에서 같은 값으로 적용한다.

- 시스템 따름: 문서 루트(`<html>`)에 `data-theme`을 두지 않는다. 기기 설정이 어두우면 어두운 화면 값을 쓴다.
- 수동 지정: 문서 루트에 `data-theme="light"` 또는 `data-theme="dark"`를 둔다. 이 값이 기기 설정보다 앞선다.
- 고른 테마는 화면을 처음 그리기 전에 적용한다. 기기에 저장한 값을 `<head>` 안에서 읽어 `data-theme`을 달아, 앱을 열 때 다른 테마가 잠깐 비치지 않게 한다. 시스템 따름 상태에서 앱을 연 채 기기 설정이 바뀌면 바로 따라 바뀐다. `[판단 67]`

```css
:root { /* 밝은 화면 값 */ }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { /* 어두운 화면 값 */ }
}
:root[data-theme="dark"] { /* 어두운 화면 값 */ }
```

### 2.2 금액의 색과 부호

| 대상 | 색 | 부호 | 예 | 출처 |
|------|----|------|----|------|
| 지출 | `color-text` | 없음 | "12,000원" | 브리핑 |

| 취소 거래 | `color-text-secondary`와 취소선 | 원래 유형의 부호 | 줄 안의 "취소" 칩 | F-215, `[판단 7]` |

- 빨강(`color-danger`)은 오류, 삭제, 예산 초과, 보낼 수 없음에만 쓴다. 지출을 빨강으로 쓰지 않는다.
- 색만으로 뜻을 전하지 않는다. 수입은 "+", 환불과 취소는 칩의 글자, 초과는 "초과"라는 글자를 함께 쓴다.
- 금액은 줄의 오른쪽 끝에 맞추고(와이어프레임 공통 배치 규칙 4) `tabular-nums`로 자릿수를 맞춘다.

### 2.3 글꼴과 글자 크기

- 글꼴: Pretendard Variable. 앱이 글꼴 파일을 직접 호스팅한다. 대체 글꼴: `-apple-system, "Apple SD Gothic Neo", system-ui, sans-serif`. 세리프 글꼴과 Inter는 쓰지 않는다.
- 금액, 날짜, 시각, 건수의 숫자는 `font-variant-numeric: tabular-nums`로 쓴다.
- 크기는 rem으로 구현한다(16px = 1rem). 브라우저와 기기의 글자 크기 설정을 따르고, 200%로 키워도 금액, 버튼, 표의 내용이 잘리거나 겹치지 않아야 한다(P-227, F-903).
- 13px보다 작은 글자는 쓰지 않는다.

그림자는 빠른 입력 버튼과 시트 종류(바닥 시트, 가운데 창, 펼친 판)에만 쓴다. 카드는 면 색(`color-surface`)과 배경색(`color-bg`)의 차이나 1px `color-border` 테두리로 나눈다. 토스트는 반전 색으로 구분하고 그림자를 쓰지 않는다. `[판단 11]`

### 2.6 아이콘, 움직임, 그래프, 초점, 층

- 아이콘: Phosphor 한 종류만 쓰고 굵기는 Regular로 통일한다. 고른 탭도 굵기를 바꾸지 않고 색만 바꾼다. 이모지는 쓰지 않는다. 글자 없이 아이콘만 있는 버튼에는 접근성 이름(`aria-label`)을 단다. 이 문서에 적은 아이콘 이름은 Phosphor의 이름이다. `[판단 15]`
- 움직임 `[판단 16]`:
  - 바닥 시트, 펼친 판, 가운데 창, 전체 화면 입력이 나타나고 사라질 때 200ms, `cubic-bezier(0.2, 0, 0, 1)`.
  - 누를 때 100ms 동안 `transform: scale(0.98)`.
  - 토스트는 150ms 동안 투명도만 바뀐다.
  - `prefers-reduced-motion: reduce`이면 위 움직임을 모두 끄고 바로 나타나고 바로 사라지게 한다.
  - 반복되는 장식 애니메이션, 숫자가 올라가는 효과, 뼈대의 번쩍임(shimmer)은 쓰지 않는다. 뼈대는 멈춘 회색 막대다.
- 그래프: 막대만 쓴다. 원 그래프와 선 그래프는 쓰지 않는다. 지출 막대는 `color-text-secondary`, 수입 막대는 `color-accent`, 예산 초과분은 `color-danger`, 막대의 남은 칸(바탕)은 `color-border`다. 막대 옆에는 금액 글자를 늘 함께 둔다. `[판단 17]`
- 키보드 초점: 2px `color-accent` 테두리를 요소 바깥으로 2px 띄워 그린다. 마우스나 손가락으로 누를 때는 보이지 않게 `:focus-visible`로 건다. `[판단 18]`
- 층 순서(아래에서 위로): 내용, 상단 바·하단 탭·사이드바·연결 없음 띠, 빠른 입력 버튼, 가림막과 바닥 시트·가운데 창·펼친 판·전체 화면 입력, 토스트. `[판단 19]`
- 안전 영역: 상단 바와 하단 탭은 `env(safe-area-inset-top)`, `env(safe-area-inset-bottom)`만큼 안쪽 여백을 더한다(iPhone 홈 화면 웹앱, F-120). 브라우저 위쪽 색(`theme-color`)은 지금 적용된 테마의 `color-bg`에 맞추고, 테마가 바뀌면 함께 바꾼다. `[판단 20]`

## 3. 문구 규칙

### 3.1 기본

- 해요체로 짧게 쓴다. 느낌표, 이모지, em-dash는 쓰지 않는다.
- 사용자를 탓하지 않는다. "잘못 입력하셨습니다" 대신 "1원부터 입력할 수 있어요"처럼 할 수 있는 것을 적는다.
- 오류 문구는 "무슨 일이 있었는지 + 무엇을 하면 되는지" 두 부분으로 쓴다. 예: "연결이 끊겨 저장하지 못했어요. 연결되면 자동으로 보낼게요."
- 부탁은 "~해 주세요"로 쓴다.
- 마침표: 두 문장 이상인 문구는 문장마다 마침표를 찍는다. 한 문장짜리 토스트, 버튼, 칩, 탭 이름, 칸 이름에는 찍지 않는다. `[판단 21]`
- 버튼은 동사로, 되도록 3단어(띄어쓰기로 나눈 덩어리) 이하로 쓴다. 예: "저장", "다시 시도", "장부 만들기". 기능정의서가 이름을 정한 버튼은 3단어를 넘어도 그 이름을 쓴다(예: "인증 메일 다시 보내기"). 버튼 글자는 한 줄에 들어가야 한다. `[불일치 9]`
- 기능정의서와 와이어프레임이 따옴표로 적은 문구(예: F-908 "연결이 없다. 새 거래 입력만 된다")는 뜻을 바꾸지 않고 해요체로 옮겨 쓴다. `[판단 21]`

## 4. 공통 상태·예외 규칙

화면별 설명의 기본값이다. 화면마다 네 가지 예외(4.1~4.4)를 빠짐없이 적는다.

### 4.1 비로그인 상태

- 로그인 없이 볼 수 있는 화면은 A-01, A-02, A-03, A-04, A-05, A-06, A-07, A-08, A-09와 열람 링크로 여는 A-10이다(P-111, P-311). 그 밖의 모든 화면은 로그인이 필요하다.
- 로그인이 필요한 화면에 로그인 없이 들어오면 로그인(A-02)으로 보내고, 가려던 주소를 기억했다가 로그인 뒤 그 주소로 돌려보낸다(F-011). 돌아간 주소가 볼 수 없는 장부의 것이면 P-903에 따라 N-01 또는 N-02를 보인다.
- 쓰던 중에 로그인이 풀리면(30일 동안 통신이 없었거나 처음 로그인한 때부터 180일이 지났거나(P-106), 다른 기기에서 비밀번호를 바꾸었거나(P-108) 모든 기기에서 로그아웃한 경우(P-109)) `[판단 25]`:
  - 다음 서버 요청에서 알게 된다. 그 순간 입력 화면에 쓰던 값을 기기에 남기고 로그인 화면을 띄운다. 로그인 화면 맨 위에 "로그인이 풀렸어요. 다시 로그인해 주세요."를 보이고, 남긴 값이 있으면 "쓰던 내용은 이 기기에 남아 있어요."를 덧붙인다(3.4).
  - 같은 계정으로 다시 로그인하면 원래 화면으로 돌아가 남긴 값을 칸에 다시 채운다. 저장은 사용자가 다시 누른다. 다른 계정으로 로그인하면 채우지 않는다.
  - 보내지 않은 입력(B-05)은 지우지 않는다. 기기 데이터(저장한 내역, 쓰던 값, 보내지 않은 입력)는 계정별로 나눠 두고 로그인한 계정의 것만 보인다. 기기 데이터를 지우는 것은 사용자가 직접 로그아웃한 경우(F-016, F-017)뿐이다.
- 공통 틀(B 그룹)은 로그인한 상태에서만 그려진다. 그래서 B 그룹 화면의 비로그인 행은 "공통 틀이 그려지지 않는다"가 기본이다.

### 4.2 데이터 없음

- 목록이나 내용이 놓일 자리에 그림 없이 한 줄 설명과 주 버튼 하나를 둔다. 설명은 무엇을 하면 그 자리가 채워지는지 적는다(P-901, F-904).
- 배치: 목록 자리 맨 위에서 40px 아래, 가운데 정렬. 설명은 `text-body`, `color-text-secondary`. 버튼은 설명 아래 16px에 주 버튼 모양으로 두고 폭은 글자에 맞춘다. `[판단 26]`
- 보기 전용 구성원에게는 버튼을 숨기고 설명만 보인다. 설명도 할 수 없는 행동을 권하지 않도록 따로 쓴다. 예: 편집 이상 "거래를 입력하면 여기에 보여요"와 "거래 입력", 보기 전용 "아직 거래가 없어요". `[판단 27]`
- 검색·필터 결과가 없으면 "조건에 맞는 거래가 없어요"와 "조건 지우기"를 보인다. "조건 지우기"는 조회 동작이라 보기 전용에게도 보인다.
- 화면 일부만 비는 경우(홈의 진행 중 이벤트 등)는 화면별 설명을 따른다. 기능정의서가 "없으면 숨긴다"고 정한 영역(F-115, F-117 등)은 숨긴다.
- 채울 방법을 권할 것이 없는 화면(예: B-05가 비면 모두 보낸 것이다)은 설명만 두고 버튼을 두지 않으며, 그 사실을 화면별 설명에 적는다.

### 4.3 네트워크 오류

연결 상태는 브라우저의 online, offline 신호와 요청의 실패(응답 없음)를 함께 보고 정한다. 요청이 연결 문제로 실패하면 곧바로 연결 없음으로 본다. `[판단 28]`

| 구분 | 연결이 없을 때 보이는 것 | 근거 |
|------|--------------------------|------|
| 모든 화면 | 상단 바 바로 아래(넓은 화면은 내용 영역 맨 위)에 연결 없음 띠(6.1의 (6)) | F-908 |
| 기기에 저장하는 읽기 화면: 홈(C-01), 내역(D-01), 달력(D-02), 계좌 목록(G-01), 계좌 상세(G-03, 기기에 저장된 계좌 값과 최근 31일 거래), 카테고리 관리(H-01), 기기에 있는 거래의 상세(D-06), 장부 전환기(B-02), 보내지 않은 입력 목록(B-05) | 기기에 저장한 마지막 데이터를 읽기 전용으로 보인다. 잔액과 합계 옆에 "{시각} 기준"(3.2 형식)을 붙인다. 저장 범위(오늘을 포함한 지난 31일) 밖의 달로 옮기면 그 자리에 "연결되면 볼 수 있어요"를 보인다 | P-902, F-908, D-06과 G-03은 `[판단 28]` |
| 그 밖의 읽기 화면(검색, 통계, 이벤트, 휴지통, 미확인 검토, 장부와 공유 등) | 연결 없이 새로 들어가면 기기에 남은 데이터가 없으므로 내용 자리에 "불러오지 못했어요."와 "연결되면 자동으로 불러올게요."를 보인다. 버튼은 두지 않고, 연결이 돌아오면 저절로 다시 불러온다(F-908). 보던 중에 연결이 끊기면 이미 불러온 내용은 지우지 않고 잔액과 합계 옆에 "{시각} 기준"을 붙여 그대로 둔다(2026-11-20 설계자 결정). 공통 틀은 그대로 보인다 | P-902, F-908, `[판단 68]` |
| 새 거래 입력(빠른 입력, D-04 새로 만들기, D-05) | 연결이 없어도 저장 버튼은 누를 수 있다. 저장하면 기기에 쌓고 토스트 "기기에 저장했어요. 연결되면 보낼게요."를 보인다. 쌓인 입력은 연결되면 오래된 것부터 보낸다(B-05) | P-225, F-103, F-105 |
| 거래 수정, 삭제, 승인취소, 취소 되돌리기, 복원, 완전히 지우기, 이벤트 소속 바꾸기 | 기기에 쌓지 않는다(새 거래만 쌓는다). 이 동작의 버튼은 비활성으로 두고(5.1의 비활성 모양) 따로 문구를 붙이지 않는다. 이유는 연결 없음 띠가 알린다 | P-225, F-103, 기능정의서 3장 머리, `[불일치 2]` `[불일치 3]` |
| 서버가 꼭 필요한 그 밖의 동작(로그인, 가입, 초대, 구성원 관리, 가져오기, 내보내기, 열람 링크, 계좌·카테고리·이벤트·예산·반복 거래의 저장, 설정 저장, 지금 보내기 등 기능정의서에 "연결 필요"로 적힌 동작) | 바로 위 줄과 같다. 비활성으로 두는 것은 서버로 요청을 보내는 버튼(저장, 실행 버튼과 확인 창을 여는 동작 버튼)이다. 입력 화면이나 하위 화면으로 가는 버튼과 줄은 막지 않는다. 들어간 입력 화면은 값을 쓸 수 있고 저장 버튼만 비활성이며, 연결이 돌아오면 바로 누를 수 있게 된다 | 기능정의서 3장 머리, F-107, `[불일치 3]`, 범위는 `[판단 69]` |
| 누를 때는 연결이 있었는데 요청 중에 연결이 끊김 | 실행하지 못한 동작의 자리에 "연결이 끊겨 ~하지 못했어요. 연결되면 다시 시도해 주세요."와 "다시 시도"를 보인다. 연결이 없는 동안 "다시 시도"는 비활성이다. 새 거래 저장이면 문구 없이 기기에 쌓는다(P-904) | 브리핑, P-904, `[판단 31]` |
| 서버 오류(5xx), 응답 지연(요청 뒤 15초 동안 응답 없음) | 같은 자리에 "문제가 생겨 ~하지 못했어요. 잠시 후 다시 시도해 주세요."와 "다시 시도"를 보인다. 입력 화면은 입력한 값을 지우지 않는다. 새 거래 저장이 서버 오류로 실패하면 기기에 쌓지 않고 입력 화면에 그대로 둔다(연결 문제로 실패한 것만 쌓는다). 읽기 화면을 불러오지 못하면 내용 자리에 "불러오지 못했어요."와 "잠시 후 다시 시도해 주세요.", "다시 시도"를 보인다 | 브리핑, F-907, P-904, 15초는 `[판단 29]` |
| 같은 서버 오류가 되풀이됨 | 오류 문구 아래에 "마지막으로 맞춘 시각 {시각}"을 함께 보인다. "되풀이"는 같은 화면에서 "다시 시도"가 연달아 두 번 실패한 경우다 | F-907, `[판단 30]` |

정리하면, 연결이 없을 때는 버튼을 비활성으로 두어 미리 막고, 연결된 상태에서 보낸 요청이 실패하거나 늦으면 그 자리에 오류 문구와 "다시 시도"를 보인다(2026-11-20 설계자 결정, `[불일치 3]`).

연결이 없어 비활성인 버튼의 안내(2026-11-20 설계자 채택, 01 화면설계서의 작성자 판단 72):

- 연결 없음 띠가 보이는 화면에서는 따로 문구를 붙이지 않는다. 띠가 이유를 알린다.
- 띠가 보이지 않는 곳에서는 비활성 버튼 바로 위에 한 줄 안내를 보인다. 문형 "연결되면 ~할 수 있어요"(예: "연결되면 로그인할 수 있어요", "연결되면 저장할 수 있어요"). 모양은 4.4의 비활성 이유와 같다(`text-caption`, `color-text-secondary`).
- 띠가 보이지 않는 곳: 공통 틀이 없는 A 그룹과 첫 실행 안내(C-02), 띠를 가리는 바닥 시트와 확인 창 안, 전체 화면 입력. 전체 화면 입력은 머리 아래에 띠가 있지만(6.1) 저장 버튼이 화면 맨 아래에 있어 띠와 떨어져 있으므로 같이 안내한다.
- 요청 중에 연결이 끊겨 "연결이 끊겨 ~하지 못했어요." 문구가 이미 버튼 위에 보이는 동안에는 "연결되면 ~할 수 있어요" 줄을 덧붙이지 않는다. 한 버튼 위에는 한 줄만 둔다(2026-11-20 설계자 채택, 03 화면설계서의 작성자 판단 64).
- 연결이 돌아오면 안내를 지우고 버튼을 다시 누를 수 있게 한다.

오류 문구를 보이는 "그 자리"는 다음과 같다. `[판단 31]`

- 버튼 하나가 일으킨 동작이면 그 버튼 바로 위. 입력 화면이면 화면 맨 아래에 고정한 저장 버튼 바로 위다(와이어프레임 N-03 메모).
- 확인 창 안에서 일으킨 동작이면 창의 버튼 바로 위. 이때 실행 버튼의 글자는 "다시 시도"로 바뀐다.
- 목록 줄 안의 동작이면 그 줄 바로 아래.
- 모양: `text-secondary` 크기, `color-danger` 글자, 앞에 WarningCircle 아이콘 20px. "다시 시도"는 글자 버튼이다(확인 창 안에서는 실행 버튼이 그 역할을 한다). "다시 시도"는 같은 동작을 같은 값으로 다시 보낸다.
- 연결이 끊기면 열려 있던 확인 창의 실행 버튼과 입력 화면의 저장 버튼(새 거래 입력은 빼고)도 비활성이 된다. 연결이 돌아오면 비활성으로 둔 버튼을 바로 다시 누를 수 있게 하고, 데이터를 다시 불러오며(F-908), 쌓인 입력을 자동으로 보낸다(F-105). 실패한 동작을 저절로 다시 하지는 않는다.

### 4.4 입력값 오류

- 문구 자리: 해당 입력칸 바로 아래(도움말이 있으면 도움말 아래). `text-secondary` 크기, `color-danger` 글자, 앞에 WarningCircle 아이콘 20px. 칸 테두리는 2px `color-danger`.
- 검사 시점: 칸을 벗어날 때와 제출할 때. 입력하는 동안에는 새 오류를 띄우지 않는다. 이미 오류가 보이는 칸은 고칠 때마다 다시 검사해, 맞으면 바로 문구를 지운다. `[판단 32]`
- 제출 버튼은 기본으로 항상 누를 수 있다. 누르면 모든 칸을 검사하고, 오류가 있으면 보내지 않고 화면 위쪽부터 첫 번째 오류 칸으로 초점을 옮기며 그 칸이 보이게 스크롤한다. 예외는 두 가지다. 연결이 없을 때 서버가 필요한 버튼(4.3)과, 기능정의서나 와이어프레임이 비활성으로 정한 버튼(아래 표)이다. `[불일치 4]`

- 비활성인 동안 버튼 바로 위에 이유를 한 줄 보인다(`text-caption`, `color-text-secondary`). 예: "필수 약관에 모두 동의하면 가입할 수 있어요", "날짜와 금액 열을 고르면 가져올 수 있어요", "{N}초 뒤에 다시 보낼 수 있어요". 연결 없음 때문에 비활성인 버튼은 4.3을 따른다(띠가 보이면 문구 없음, 띠가 보이지 않는 곳에서는 "연결되면 ~할 수 있어요"). `[판단 70]`
- 기능정의서가 "버튼 대신 안내를 보여 준다"고 정한 곳(F-508 거래가 있는 계좌의 삭제, F-805 마지막 장부의 삭제, F-808 소유자와 마지막 장부의 나가기)은 비활성 버튼을 두지 않고 버튼 자리에 안내 문장을 둔다.
- 입력한 값은 지우지 않는다. 비밀번호 칸도 지우지 않는다. `[판단 33]`
- 서버가 거부한 값(겹치는 이름, 맞지 않는 비밀번호 등)도 같은 자리에 보인다. 서버가 어느 칸인지 알려 주지 않는 오류는 제출 버튼 바로 위에 보인다.
- 검증 규칙(길이, 범위, 형식)은 기능정의서 값을 그대로 쓴다. 화면별 설명은 칸마다 규칙과 문구를 적는다. 여러 화면에 나오는 칸의 기본 문구는 다음과 같다.

| 칸 | 규칙 | 문구 | 근거 |
|----|------|------|------|
| 금액 | 1원 이상 9,999,999,999원 이하의 정수 | "1원부터 9,999,999,999원까지 입력할 수 있어요" | P-201, F-201 |
| 날짜 | 2000년 1월 1일부터 오늘로부터 1년 뒤까지 | "2000년 1월 1일부터 {1년 뒤 날짜}까지 고를 수 있어요" (날짜 고르기가 범위 밖 날짜를 고를 수 없게 하므로 서버가 거부한 경우에만 나온다) | P-202, F-204 |
| 가맹점/내용 | 100자 이하 | "100자까지 쓸 수 있어요" | P-214 |
| 메모 | 500자 이하 | "500자까지 쓸 수 있어요" | P-214 |
| 이메일 | 이메일 형식 | "이메일 주소 형식을 확인해 주세요" | P-101 |

| 표시 이름 | 앞뒤 공백을 지운 1~20자 | "1자부터 20자까지 쓸 수 있어요" | P-101 |
| 비어 있는 필수 칸 | 값이 있어야 한다 | 쓰는 칸 "{칸 이름}을 입력해 주세요", 고르는 칸 "{칸 이름}을 골라 주세요". 조사는 칸 이름에 맞춘다(예: "금액을 입력해 주세요", "계좌를 골라 주세요") | `[판단 34]` |

- 글자 수 제한이 있는 칸은 제한을 넘는 입력을 막지 않고(붙여넣기 포함) 오류로 알린다. 제한의 80%를 넘으면 칸 아래 오른쪽에 "{현재 글자 수}/{최대}"를 `text-caption`으로 보인다. `[판단 35]`

### 4.5 그 밖의 공통 상태

- 불러오는 중: 실제 배치와 같은 모양의 뼈대(멈춘 `color-border` 막대)를 보인다. 요청 뒤 300ms가 지나도 응답이 없을 때부터 뼈대를 보여 깜빡임을 줄인다. 기기에 저장된 데이터가 있으면 뼈대 대신 저장된 데이터를 먼저 보이고 새 데이터가 오면 바꾼다. 돌아가는 원은 버튼 안의 처리 중 표시에만 쓴다. `[판단 36]`
- 처리 중: 누른 버튼을 비활성으로 바꾸고 글자 자리에 처리 중 표시(돌아가는 원 20px)를 둔다. 버튼 폭은 그대로다. 두 번 눌리지 않는다. 입력 화면이면 처리 중에 칸도 바꿀 수 없다. 끝나면(성공이든 실패든) 버튼이 원래대로 돌아온다. 접근성: 처리 중인 버튼에 `aria-busy="true"`. `[판단 37]`
- 권한: 권한 없는 버튼은 숨긴다. 흐리게 두지 않는다(기능정의서 1.3). 주소를 직접 열거나 요청을 직접 보내 서버가 거부하면 N-02를 보인다.
- 버전 충돌: 다른 기기가 먼저 고친 거래를 저장하거나 바꾸려 하면 N-04를 띄운다(P-217, F-909).
- 찾을 수 없음과 접근 권한 없음: P-903에 따라 N-01, N-02.
- 화면 상태 유지: 뒤로 가기로 돌아오면 스크롤 위치, 불러온 목록, 고른 달, 필터를 그대로 둔다. `[판단 38]`

## 5. 공통 컴포넌트

### 5.1 버튼

| 종류 | 모양 | 쓰는 곳 |
|------|------|---------|
| 주 버튼 | `color-accent` 바탕, `color-on-accent` 글자(`text-body-strong`), 높이 48px, 모서리 10px | 화면마다 하나(와이어프레임 공통 배치 규칙 1). 입력 화면의 저장 버튼은 화면 맨 아래에 고정하고 좌우 16px 여백을 둔 전체 폭이다 |
| 위험 버튼 | `color-danger` 바탕, `color-on-danger` 글자, 크기는 주 버튼과 같다 | 확인 창 안에서 지우거나 없애는 동작의 실행 버튼(삭제, 완전히 지우기, 버리기, 장부 삭제, 구성원 내보내기, 탈퇴 신청, 초대 취소, 열람 링크 폐기, 가져오기 되돌리기) |
| 보조 버튼 | `color-surface` 바탕, 1px `color-border-strong` 테두리, `color-text` 글자, 높이 44px, 모서리 10px | 주 버튼 말고 화면에 버튼이 더 필요할 때, 확인 창의 "닫기" |
| 글자 버튼 | 바탕과 테두리 없음, `color-accent` 글자(지우거나 없애는 동작이면 `color-danger`), 누르는 영역 44px | 줄 안의 동작(버리기, 복사, 고쳐서 보내기), "다시 시도", 링크 |
| 아이콘 버튼 | 아이콘 24px, 누르는 영역 44 x 44px, `aria-label` 필수 | 닫기(X), 뒤로(CaretLeft), 이전·다음 달(CaretLeft, CaretRight) |

- 화면 맨 아래에 따로 떼어 두는 되돌릴 수 없는 동작(와이어프레임 공통 배치 규칙 3)은 화면에서는 위험색 글자 버튼으로 두고, 누르면 확인 창의 위험 버튼으로 실행한다. 한 화면의 주 버튼이 하나라는 규칙을 지키기 위해서다. `[판단 39]`
- 버튼 글자는 한 줄이다. 두 버튼이 한 줄에 들어가지 않으면(글자 크기를 키운 경우 등) 위아래로 쌓고, 실행 버튼을 위에 둔다.
- 누를 때 2.6의 눌림 효과를 쓴다.
- 비활성 모양: 누를 수 없는 버튼은 `color-border` 바탕과 `color-text-secondary` 글자로 바꾸고 `aria-disabled="true"`를 단다. 글자 버튼은 글자만 `color-text-secondary`가 된다. 비활성을 쓰는 곳은 세 가지뿐이다: 처리 중(4.5), 연결이 없을 때 서버가 필요한 버튼(4.3), 기능정의서가 비활성으로 정한 버튼(4.4의 표). 권한이 없는 버튼은 비활성으로 두지 않고 숨긴다.

### 5.2 입력칸

- 구조(와이어프레임 공통 배치 규칙 2): 이름(위, `text-label`, `color-text`), 칸, 도움말(`text-caption`, `color-text-secondary`), 오류 문구(4.4) 순서다.
- 칸 안의 흐린 글자(placeholder)는 이름 대신 쓰지 않는다. 예시 값을 보일 때만 쓴다(예: 한 줄 입력 "예: 점심 12000", F-114).
- 칸: 높이 48px, 모서리 10px, `color-surface` 바탕, 1px `color-border-strong` 테두리, 안쪽 좌우 12px. 초점이면 2px `color-accent` 테두리, 오류면 2px `color-danger` 테두리.
- 필수 표시: 필수 칸 이름에는 아무것도 붙이지 않고, 선택 칸 이름 뒤에 "(선택)"을 붙인다. `[판단 40]`
- 고르는 칸(카테고리, 계좌 등): 같은 칸 모양에 오른쪽 CaretDown 아이콘 20px. 누르면 5.4의 고르기 시트가 열린다.
- 접근성: 이름은 `<label>`로 칸과 묶고, 도움말과 오류 문구는 `aria-describedby`로 잇는다. 오류 칸에는 `aria-invalid="true"`.

### 5.3 금액 입력칸

`[판단 41]` (값의 범위는 P-201)

| 항목 | 정의 | 근거 |

| 쉼표 | 입력하는 동안 세 자리마다 쉼표를 자동으로 넣는다. 커서는 방금 친 숫자 바로 뒤에 둔다. 쉼표 바로 뒤에서 지우기를 누르면 쉼표 앞의 숫자를 지운다 | `[판단 41]` |
| "원" | 칸 안 오른쪽 끝에 고정 글자 "원"(`color-text-secondary`). 지울 수 없다 | 와이어프레임 D-04 (3) |
| 정렬 | 오른쪽 정렬, `tabular-nums` | 브리핑 |

| 붙여넣기 | 숫자만 골라 넣는다("12,000원"은 12,000). 숫자가 10자리를 넘으면 넣지 않고 최대 문구를 보인다 | `[판단 41]` |
| 음수 | 받지 않는다. 음수가 필요한 칸(은행·현금 계좌의 시작 잔액, F-502)은 이 칸에 부호 고르기를 더하며, 배치는 03-accounts-import-sharing.md의 G-02에서 정한다 | P-201, F-502 |

### 5.4 바닥 시트와 펼친 판

- 휴대폰 배치: 화면 아래에서 200ms 동안 올라온다. `color-surface` 바탕, 위쪽 두 모서리 12px, 2.4의 그림자. 뒤에는 `color-scrim` 가림막을 깐다.
- 구성: 맨 위 가운데 손잡이(36 x 4px, 완전히 둥글게, `color-border-strong`), 머리(왼쪽 제목 `text-title`, 오른쪽 "닫기" 아이콘 버튼 X), 내용(넘치면 시트 안에서 스크롤), 맨 아래 고정 버튼(있을 때).
- 높이: 내용만큼, 최대 화면 높이의 90%.
- 닫기: X, 가림막 누르기, 아래로 끌어내리기, Esc 키. 처리 중에는 닫히지 않는다. 작은 시트(고르기, 비밀번호 바꾸기 판 등)는 쓰던 값이 있어도 확인 없이 닫고 그 값은 버린다. 확인을 받는 것은 5.5의 전체 화면 입력뿐이다. `[판단 42]`
- 고르기 시트(카테고리, 계좌, 결제한 사람, 이벤트 고르기): 하나만 고르는 시트는 줄을 누르면 고르고 바로 닫힌다. 여러 개를 고르는 시트(필터, 거래 넣기)는 맨 아래 고정 버튼을 눌러야 적용되고 닫힌다(버튼 이름은 화면별로 정한다). 지금 고른 값에는 Check 아이콘(`color-accent`)과 `aria-selected`.
- 초점: 열리면 시트 제목으로 초점을 옮기고, 열려 있는 동안 초점이 시트 밖으로 나가지 않는다. 닫히면 연 버튼으로 초점을 돌린다. 뒤 화면은 스크롤되지 않는다. `role="dialog"`, `aria-modal="true"`.
- 넓은 화면: 입력칸에서 여는 고르기 시트는 칸 바로 아래에 붙는 펼친 판(폭은 칸 폭과 320px 중 큰 값, 최대 높이 360px, 모서리 12px, 2.4의 그림자, 가림막 없음)이 된다. 그 밖의 시트(비밀번호 바꾸기 판, 거래 넣기, 확인 창)는 가운데 창(폭 480px, 모서리 12px, 가림막 있음)이 된다(와이어프레임 공통 배치 규칙 9). `[판단 43]`
- 장부 전환기(B-02)처럼 상단 바에서 아래로 펼치는 판은 위 규칙을 따르되 위에서 아래로 펼친다(6.3).

### 5.5 전체 화면 입력

대상은 D-04, D-05, F-02, G-02, I-02, L-02, L-06이다(와이어프레임 00-common 3.1).

- 휴대폰 배치: 아래에서 200ms 동안 올라와 화면 전체를 덮는다. 하단 탭과 빠른 입력 버튼이 없다. 머리는 왼쪽 "닫기" 아이콘 버튼(X), 그 오른쪽 화면 이름(`text-title`). 저장 버튼은 맨 아래에 고정하고, 화면 키보드가 올라오면 키보드 바로 위로 올린다. 연결 없음 띠는 머리 바로 아래에 보인다(와이어프레임 00-common 3.1).
- 닫기: 연 뒤에 바꾼 값이 있으면 확인 창을 띄운다. 제목 "쓰던 내용을 버릴까요?", 설명 "저장하지 않은 내용은 사라져요.", 버튼 "계속 쓰기"(보조 버튼)와 "버리기"(위험 버튼). 바꾼 값이 없으면 바로 닫는다. 브라우저의 뒤로 가기도 같다. `[판단 44]`
- 넓은 화면: 목록 화면에서 열면 오른쪽 칸(440px)에 들어간다. 그 밖의 화면에서 열면 내용 영역에서 폭을 560px로 제한한 같은 배치로 연다(와이어프레임 02 D-04 넓은 화면). `[판단 44]`

### 5.6 확인 창

- 휴대폰 배치는 바닥 시트, 넓은 화면은 가운데 창이다(와이어프레임 공통 배치 규칙 9).
- 구성: 제목(묻는 말, `text-title`, 예: "거래를 삭제할까요?"), 설명(결과를 한두 문장, `text-body`, `color-text-secondary`), 필요하면 입력칸이나 고르기, 맨 아래 버튼 두 개.
- 버튼: 왼쪽 "닫기"(보조 버튼), 오른쪽 실행 버튼. 두 버튼은 같은 폭으로 한 줄에 둔다. 한 줄에 들어가지 않으면 실행 버튼을 위로 쌓는다. 휴대폰과 넓은 화면이 같다. `[판단 45]`
- 실행 버튼의 글자는 동작 이름을 그대로 쓴다("삭제", "승인취소", "완전히 지우기"). "확인", "예"는 쓰지 않는다. 물러나는 버튼은 늘 "닫기"다(예외: 5.5의 "계속 쓰기"). `[판단 24]` `[불일치 10]`
- 실행 버튼 모양: 지우거나 없애는 동작은 위험 버튼, 그 밖은 주 버튼(5.1).
- 설명에는 되돌릴 수 있는지와 그 방법을 기능정의서대로 적는다. 예: 삭제 "휴지통으로 옮겨요. 30일 안에 복원할 수 있어요."(F-227), 완전히 지우기 "되돌릴 수 없어요."(F-231), 장부 삭제 "30일 안에는 복구할 수 있어요."(F-805).
- 첫 초점: 위험 버튼이 있는 창은 "닫기"에, 그 밖의 창은 실행 버튼에 둔다. Enter 키는 초점이 있는 버튼을 누른다. `[판단 46]`
- 처리: 실행 버튼을 누르면 그 버튼에 처리 중 표시를 둔다. 성공하면 창을 닫고 필요하면 토스트를 보인다. 실패하면 창을 닫지 않고 버튼 바로 위에 4.3의 문구를 보이며 실행 버튼 글자를 "다시 시도"로 바꾼다.
- 연결이 없을 때: 서버가 필요한 동작의 확인 창은 그 창을 여는 버튼이 비활성이라 열리지 않는다(4.3). 창이 열려 있는 동안 연결이 끊기면 실행 버튼이 비활성으로 바뀌고 그 바로 위에 "연결되면 ~할 수 있어요"를 보이며(창이 띠를 가리므로, 4.3), 연결이 돌아오면 안내를 지우고 다시 누를 수 있게 한다. 기기 안의 동작(B-05의 버리기 등)은 연결과 관계없이 열리고 실행된다.
- 열리고 닫힐 때의 초점과 닫는 방법은 5.4와 같다. 처리 중에는 닫히지 않는다.

### 5.10 목록 불러오기

- 방식: 끝까지 내리면 다음 50건을 불러오는 이어 불러오기(무한 스크롤)다. 페이지 번호는 쓰지 않는다(P-232).
- 시점: 목록 끝이 화면 아래 한 화면 높이 안에 들어오면 다음 50건을 요청한다. 불러오는 동안 목록 끝에 뼈대 줄 3개를 보인다. `[판단 51]`

- 끝: 더 불러올 것이 없으면 아무것도 덧붙이지 않는다.
- 연결이 없을 때: 기기에 저장된 범위(오늘을 포함한 지난 31일)까지만 보이고, 그보다 오래된 거래가 있는 달이면 목록 끝에 "연결되면 볼 수 있어요"를 보인다(F-908).

- 돌아왔을 때: 4.5의 화면 상태 유지(불러온 목록과 스크롤 위치를 그대로 둔다).

## 7. 다른 파일이 지킬 것

- 화면마다 1.3의 순서로 적는다. 예외 표의 네 행은 이 문서 4절이 기본값이다.
- 공통 컴포넌트(5절)는 이름으로 가리키고 같은 모양과 동작을 다시 정하지 않는다. 화면에서만 다른 점(버튼 이름, 시트의 줄 구성 등)만 적는다.
- 문구는 3절을 따른다. 3.4에 있는 상황은 그 문구를 그대로 쓴다.
- 새로 정한 세부는 각 파일 끝의 "작성자 판단" 표에, 다른 문서와 어긋나는 점은 "발견한 불일치" 표에 모은다.
