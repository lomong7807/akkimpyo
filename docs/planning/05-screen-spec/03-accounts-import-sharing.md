## 읽기 전에

### 표기

- 화면 순서와 요소 번호는 와이어프레임 03과 같다. 요소 표의 `#` 는 와이어프레임 그림의 `(n)` 이다. 상태별 그림(그림 가, 나, 다)에만 나오는 요소도 같은 번호로 적었다.
- 큰따옴표 안의 글자는 화면에 그대로 보이는 문구다. `'우리은행 예전통장'` 처럼 작은따옴표로 감싼 이름과 예시 숫자·날짜는 실제 값으로 바뀐다.
- `[2]`, `[3]` 은 그 요소나 문장이 들어가는 단계다(IA와 같다). 단계가 오지 않은 요소는 보이지 않는다.
- 권한은 기능정의서 1.3의 말을 쓴다. "구성원 전체", "편집 이상"(소유자와 편집 가능), "소유자만".
- 와이어프레임은 해라체("숨긴다")와 `2026-11-18` 날짜를 썼지만, 이 문서의 화면 문구는 문구 규칙대로 해요체와 `11월 18일 (수)`(다른 해는 `2025년 11월 18일`)로 바꿔 적었다. 날짜와 시각을 함께 쓰면 `11월 25일 (수) 14:30` 이다.
- 이 문서의 화면은 모두 로그인이 필요하다(P-111). 그래서 예외 표의 "비로그인 상태" 행은 해당 없음이 아니라, 로그인 화면(A-02)으로 보냈다가 그 화면 주소로 돌려보내는 동작을 적는다.

### 이 문서 안에서 되풀이하는 규칙

00-common의 공통 규칙(공통 틀, 뼈대, 처리 중 표시, 토스트, 확인 창, 연결 없음 띠, 입력값 오류 표시)을 따른다. 아래는 이 문서의 화면에서 같은 방식으로 되풀이되는 것만 모아 번호를 붙였다. 화면별 예외 표에는 그 화면에서 실제로 보이는 문구를 적고, 근거로 이 번호를 단다.

| 번호 | 규칙 |
|------|------|
| R1 | 연결과 서버 오류는 00-common 4.3을 따른다. 연결이 없으면 서버로 요청을 보내는 버튼(저장, 실행, 확인 창을 여는 동작 버튼)은 문구 없이 비활성이고 이유는 연결 없음 띠가 알린다. 연결 없음 띠가 가려지는 곳(전체 화면 입력 G-02, I-02, L-02, L-06, H-01의 판, 확인 창)에서는 비활성 버튼 바로 위에 보조 글자 한 줄 "연결되면 {동작}할 수 있어요"를 보이고, 연결이 돌아오면 지운다. 요청 중에 끊겨 아래의 "연결이 끊겨" 문구가 보이는 동안에는 이 줄을 덧붙이지 않는다(작성자 판단 64). 화면으로 가는 버튼과 줄은 막지 않으며, 들어간 입력 화면은 값을 쓸 수 있고 저장 버튼만 비활성이다. 연결이 돌아오면 바로 누를 수 있다. 요청 중에 연결이 끊기면 "연결이 끊겨 {동작}하지 못했어요. 연결되면 다시 시도해 주세요.", 서버 오류(5xx)나 15초 넘는 지연이면 "문제가 생겨 {동작}하지 못했어요. 잠시 후 다시 시도해 주세요."를 "다시 시도"와 함께 그 버튼 바로 위(확인 창이면 창의 버튼 바로 위이고 실행 버튼 글자가 "다시 시도"로 바뀐다, 목록 줄의 동작이면 그 줄 바로 아래)에 보인다. 기기에 저장하지 않는 읽기 화면은 연결이 없으면 내용 자리에 "불러오지 못했어요."와 "연결되면 자동으로 불러올게요."를 보이고 버튼 없이 연결되면 다시 불러온다. 서버 오류로 불러오지 못하면 "불러오지 못했어요.", "잠시 후 다시 시도해 주세요."와 "다시 시도"다. 입력값은 지우지 않는다(P-904). 화면별 예외 표에는 그 화면에서 비활성이 되는 버튼과 실제 문구만 적는다. |
| R2 | 확인 창은 00-common 5.6의 공통 컴포넌트를 쓴다(휴대폰과 넓은 화면 모두 왼쪽 "닫기" 보조 버튼, 오른쪽 실행 버튼, 지우거나 없애는 동작의 실행 버튼은 위험 버튼). 화면별 설명에는 제목, 설명, 실행 버튼 이름만 적는다. 이 문서에서 더 정한 것은 하나다. 창을 연 사이 대상이 바뀌어 실행할 수 없게 되면(이미 지워짐, 이미 되돌림 등) 토스트를 쓰지 않고 창의 버튼 바로 위에 그 사실을 보이며 실행 버튼을 숨기고, "닫기"를 누르면 목록을 다시 불러온다. |
| R3 | 전체 화면 입력(G-02, I-02, L-02, L-06)을 바꾼 값이 있는 채 닫을 때는 00-common 5.5의 확인 창(제목 "쓰던 내용을 버릴까요?", 왼쪽 "계속 쓰기", 오른쪽 "버리기" 위험 버튼)을 쓴다. H-01의 판은 작은 시트라 확인 없이 닫는다(00-common 5.4). 월 예산(J-01)은 시트가 아닌 하위 화면이지만 칸이 많아, 바꾼 값이 있는데 "뒤로"를 누르면 같은 확인 창을 띄운다(작성자 판단 1). |
| R4 | 잔액과 합계는 본문 글자색이고 음수이면 앞에 `-`를 붙인다(카드의 갚을 금액, 마이너스 통장). 빨강은 쓰지 않는다. 거래 금액의 색과 부호는 브리핑의 금액 색 규칙(지출은 본문색 부호 없음, 수입은 강조색 `+`, 이체는 보조 글자색)을 따른다. |
| R5 | 로그인이 풀린 채 이 문서의 화면을 열면 A-02로 보내고, 로그인 뒤 그 화면 주소로 돌아온다. 입력 중에 풀리면 입력값을 기기에 남겨 두었다가 돌아왔을 때 다시 채운다. 저장은 사용자가 다시 누른다. |
| R6 | 기능정의서의 수정 충돌 검사(P-217)는 거래에만 있다. 계좌, 카테고리, 예산, 반복 거래 규칙, 장부 이름은 나중에 저장한 값이 남는다(발견한 불일치 7번). 고치려던 대상이 그사이 지워졌으면 N-01(찾을 수 없음)을, 그사이 권한을 잃었으면 N-02(접근 권한 없음)를 보여 준다(P-903). |
| R7 | G, H, I, J, K 그룹은 현재 장부의 화면이다(K-01의 장부 선택만 기본값이 현재 장부다). 장부 전환기(B-02)로 장부를 바꾸면 같은 화면을 새 장부 기준으로 다시 불러온다. 바꾼 장부에서 권한이 모자란 화면(예: 보기 전용인 장부의 K-02)이면 그 장부의 더보기(M-01)로, 넓은 화면이면 홈(C-01)으로 간다. L-04~L-07, L-09는 장부 목록(L-01)에서 고른 장부의 화면이라 현재 장부와 다를 수 있고, 장부를 바꿔도 그대로 남는다. |

### 상태

- 불러오는 중: 자산 합계 한 줄, 묶음 머리 3개, 묶음마다 계좌 줄 2개 모양의 뼈대.
- 처리 중: 누른 "다시 보이기"만 처리 중 표시로 바뀌고 비활성이 된다. 다른 줄은 그대로 쓸 수 있다.
- 성공 뒤 동작: 다시 보이기는 (7)과 같다. G-02에서 계좌를 추가하고 돌아오면 새 계좌가 그 종류 묶음 맨 아래에 보인다(토스트는 G-02).

### 권한과 넓은 화면

- 소유자, 편집 가능: 차이 없음.
- 보기 전용: (1), (7)과 빈 상태의 "계좌 추가"가 보이지 않는다. 줄을 누르면 G-03이 열린다. 빠른 입력 버튼도 보이지 않는다(00-common).
