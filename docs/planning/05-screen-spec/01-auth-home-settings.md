## 0. 읽는 법

- 화면 하나는 들어오는 길, 요소, 상태, 예외 처리, 권한별 차이와 넓은 화면 순서로 적는다.
- 요소 표의 번호는 와이어프레임 요소 표의 번호와 같다. 와이어프레임의 상태별 그림에만 나오는 요소도 같은 표에 있다.
- 화면에 보이는 글자는 큰따옴표 안에 적는다. `{장부 이름}` 처럼 중괄호 안은 실제 값이 들어가는 자리다.
- 기능정의서와 와이어프레임의 문구는 한다체로 적혀 있다. 화면 문구는 브리핑의 문구 규칙에 따라 뜻을 바꾸지 않고 해요체로 옮겼다(작성자 판단 1).
- 날짜와 시각은 00-common 3.2의 형식을 따른다: 날짜는 올해면 `11월 20일 (금)`, 다른 해면 `2025년 11월 20일`, 시각은 24시간제 `09:05`, `15:12`, 달은 올해면 `11월`, 다른 해면 `2025년 12월`, 비율은 반올림한 정수. "오늘", "어제" 같은 상대 표현은 쓰지 않는다. 금액은 `12,345원` 이다. 수입은 강조색과 `+`, 지출은 본문 글자색에 부호 없음, 이체는 보조 글자색이다(브리핑 금액 색 규칙).
- 권한은 소유자, 편집 가능, 보기 전용이며 소유자와 편집 가능을 묶어 "편집 이상"이라고 쓴다(기능정의서 1.3).
- 단계 표시 `[1]` `[2]` `[3]` `[4]` `[출시]` 는 IA와 같다. 단계가 오지 않은 요소는 보이지 않는다.

### 0.1 이 문서에서 되풀이하는 문구

아래 문구와 규칙은 00-common 3.4(자주 쓰는 문구), 4.3(네트워크 오류), 4.4(입력값 오류)와 2026-11-20 설계자 결정을 따른다. 화면별 예외 처리 표에는 문형의 `~` 자리에 그 화면의 동작을 넣은 실제 문구를 적는다. 모양(글자 크기, 색, 아이콘)과 "그 자리"의 정의도 00-common 4.3을 따른다.

| 경우 | 보이는 자리 | 문구와 버튼 |
|------|-------------|-------------|
| 연결 없음 띠 | 상단 바 바로 아래(넓은 화면은 내용 영역 맨 위). 공통 틀이 있는 화면에만 | "연결이 없어요. 새 거래 입력만 돼요." |
| 연결이 없을 때 서버가 필요한 버튼 | 그 버튼 | 비활성으로 두고 따로 문구를 붙이지 않는다. 이유는 연결 없음 띠가 알린다. 화면으로 가는 버튼과 줄은 막지 않고, 들어간 입력 화면은 저장 버튼만 비활성이다. 새 거래 저장만 예외로 누를 수 있고 기기에 쌓는다. 연결이 돌아오면 바로 다시 눌린다(00-common 4.3). 띠가 보이지 않는 곳(공통 틀이 없는 A 그룹과 C-02, 바닥 시트, 확인 창, 전체 화면 입력)에서는 비활성 버튼 바로 위에 "연결되면 ~할 수 있어요"를 한 줄 보인다(00-common 4.3, 작성자 판단 72) |
| 누를 때는 연결이 있었는데 요청 중에 연결이 끊김 | 누른 버튼 바로 위. 확인 창이면 창의 버튼 바로 위이고 실행 버튼 글자가 "다시 시도"로 바뀐다 | "연결이 끊겨 ~하지 못했어요. 연결되면 다시 시도해 주세요." + "다시 시도"(연결이 없는 동안 비활성) |
| 연결된 상태에서 서버 오류(5xx)나 응답 지연(15초) | 위와 같은 자리 | "문제가 생겨 ~하지 못했어요. 잠시 후 다시 시도해 주세요." + "다시 시도" |
| 읽기 화면, 연결이 없고 기기에 남은 데이터도 없음 | 내용 자리 | "불러오지 못했어요."와 "연결되면 자동으로 불러올게요." 버튼은 없고 연결이 돌아오면 저절로 불러온다(F-908) |
| 읽기 화면, 연결된 상태의 서버 오류나 응답 지연 | 내용 자리 | "불러오지 못했어요."와 "잠시 후 다시 시도해 주세요.", 버튼 "다시 시도" |
| 기기에 남은 데이터를 보여 줌 | 잔액과 합계 머리 줄 오른쪽 | 오늘이면 "10:42 기준", 다른 날이면 "11월 19일 (목) 15:12 기준" |
| 쓰던 중 로그인이 풀림 | 로그인 화면(A-02) 맨 위 알림 | "로그인이 풀렸어요. 다시 로그인해 주세요." 입력 화면에 쓰던 값을 기기에 남긴 경우에만 "쓰던 내용은 이 기기에 남아 있어요."를 덧붙인다(00-common 3.4, 4.1) |
| 기능정의서가 선행 조건으로 막은 버튼이 비활성인 동안 | 그 버튼 바로 위, 작은 설명 글자(`text-caption`, 보조 글자색) | 이유 한 줄. A-03 "필수 약관에 모두 동의하면 가입할 수 있어요", A-04·A-05 "{N}초 뒤에 다시 보낼 수 있어요", M-04 "받을 장부를 고르면 발급할 수 있어요"(00-common 4.4) |

- "다시 시도"는 실패한 그 요청을 같은 값으로 다시 보낸다. 입력한 값은 비밀번호 칸까지 지우지 않는다(00-common 4.4).
- 연결이 없을 때 기기에 쌓는 것은 새 거래 입력뿐이다(P-225, F-103). 이 문서의 화면에서는 홈의 한 줄 입력(C-01 (1))과 빠른 입력이 해당한다. 거래의 수정, 삭제, 승인취소와 그 밖의 서버 동작은 연결이 필요하다.
- 제출 버튼은 기본으로 늘 누를 수 있고, 누르면 첫 오류 칸으로 초점을 옮긴다. 예외는 연결이 없을 때 서버가 필요한 버튼과, 기능정의서가 선행 조건으로 막은 버튼(A-03 (7) 약관 동의 전, A-04 (4)·(6)과 A-05 (3)의 60초 대기, M-04 (2) 받을 장부를 정하기 전)이다("발견한 불일치" 1번).
- 확인 창과 시트의 물러나는 버튼은 "닫기"다. 휴대폰과 넓은 화면 모두 왼쪽에 "닫기"(보조 버튼), 오른쪽에 실행 버튼(지우는 동작이면 위험 버튼)을 둔다. 실행 버튼 글자는 동작 이름이다(00-common 5.6). 연결이 끊기면 열려 있던 확인 창의 실행 버튼도 비활성이 되고 그 바로 위에 "연결되면 ~할 수 있어요"를 보인다(창이 띠를 가리므로, 00-common 4.3). 저장하지 않고 닫을 때 묻는 창(제목 "쓰던 내용을 버릴까요?", 왼쪽 "계속 쓰기", 오른쪽 "버리기")은 전체 화면 입력에 쓰며 이 문서의 화면에는 쓰는 곳이 없다.
- 장부를 바꿀 때의 화면 이동은 00-common의 장부 전환 규칙을 따른다. 장부 단위 화면(목록, 설정, 관리)은 같은 화면을 새 장부로 다시 불러오고, 특정 항목 화면(상세, 입력)이나 새 장부에서 권한이 모자란 화면이면 지금 탭의 첫 화면(더보기 아래 화면이면 M-01)으로 간다. 이 문서의 M-02~M-05는 장부와 관계없는 계정 설정이라 장부를 바꿔도 같은 화면이 그대로 보인다.
- 버튼 이름은 되도록 동사로 3단어 이하로 쓰되, 기능정의서에 정해진 이름은 그대로 쓴다(예: "인증 메일 다시 보내기", "내 입력 다시 적용", "홈으로", "발견한 불일치" 3번).
- 입력칸 오류 문구와 한 문장짜리 토스트·빈 상태 문구·안내 줄은 마침표 없이 적고, 두 문장 이상인 문구는 마침표를 찍는다(00-common 3.4, 4.4의 표기에 맞춤).

## A-01 소개 페이지 `[출시]`

들어오는 길: 서비스 주소를 직접 열거나 검색 결과에서 들어온다. 로그인한 상태로 들어오면 홈(C-01)으로 바로 보낸다(F-001). 공통 틀이 없다.

### 디자인 방향

이 화면만 랜딩 페이지라서 `design-taste-frontend` 스킬을 적용했다. 색과 글꼴은 브리핑의 앱 규칙을 그대로 쓴다. 소개 문구와 구성은 F-001이 화면설계서에 맡겼으므로 아래 구역 구성, 문구, 그림, 예시 데이터는 모두 작성자 판단이다(작성자 판단 19).

- 디자인 읽기: 혼자 또는 함께 쓸 가계부를 찾는 국내 사용자(회사와 밖에서 기기를 바꿔 쓰는 30대 직장인, 맞벌이 부부, 모임 총무)를 위한 소비자 앱 소개 페이지. 돈을 다루므로 차분하고 믿음을 주는 말투를 쓰고, 꾸밈 대신 실제 앱 화면과 실제 숫자를 주인공으로 둔다.
- 세 다이얼: 변화(DESIGN_VARIANCE) 6, 움직임(MOTION_INTENSITY) 3, 밀도(VISUAL_DENSITY) 3. 신뢰가 먼저인 서비스라 스킬 표의 "trust-first"와 "landing" 사이로 정했고, 움직임은 앱과 같은 차분한 규칙(브리핑 움직임)에 맞춰 3으로 낮췄다. 숫자 예시가 들어가므로 여백을 넉넉히 둔다.
- 디자인 시스템: 외부 디자인 시스템을 쓰지 않는다. 앱과 같은 색 토큰, Pretendard, 모서리 세 종류(카드·그림 12px, 버튼 10px, 칩 완전히 둥글게)를 쓴다.
- 테마: 기기 설정(`prefers-color-scheme`)을 따르고 구역마다 테마를 바꾸지 않는다. 밝은 화면과 어두운 화면 모두 브리핑 색을 쓴다.
- 움직임: 자동으로 움직이는 것은 없다. 버튼을 누를 때 살짝 눌리는 효과(98%로 줄어듦)와 링크에 마우스를 올렸을 때 밑줄만 둔다. `prefers-reduced-motion` 이면 눌림 효과도 끈다.
- 그림: 실제 앱을 예시 데이터로 캡처한 이미지를 쓴다. 밝은 화면용과 어두운 화면용을 한 벌씩 만들어 `<picture>` 의 `prefers-color-scheme` 으로 고른다. div로 그린 가짜 앱 화면은 쓰지 않는다. 앱이 완성되기 전에는 가로세로 비율을 잡아 둔 빈 자리만 두고 출시 전에 캡처로 채운다. 그림에는 그림자를 넣지 않고 구분선 색 1px 테두리와 12px 모서리를 둔다(브리핑 그림자 규칙).
- 글자 크기: 랜딩 페이지라 앱보다 큰 글자를 쓴다. 첫 화면 머리 문구는 넓은 화면 44px, 휴대폰 30px, 굵게, 줄 간격 1.25. 구역 제목은 넓은 화면 28px, 휴대폰 22px, 굵게. 설명 글은 넓은 화면 18px, 휴대폰 16px, 보조 글자색, 줄 간격 1.6. 그 밖의 글자는 앱 규칙과 같다(작성자 판단 3).
- 검색 노출: 허용한다(F-001). 문서 제목은 "아낌표: 누가 어디서 적어도 같은 장부", 검색 설명(meta description)은 요소 4의 보조 문구와 같다.
- 쓰지 않는 것: 가운데 정렬 첫 화면, 같은 크기 카드 세 개, 구역 제목 위의 작은 영문 라벨(eyebrow), 구역 번호, 스크롤 안내, 장식용 점, 버전 표시, 가격 구역(P-114), em-dash.

- 인증하지 않은 계정 `[출시]`: 로그인하지 않고 이메일 인증 안내(A-04)로 보낸다(F-009). (2)의 이메일을 넘긴다.
