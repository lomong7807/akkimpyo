# 1단계 조각(1A, 1B, 1C)

- 작성일: 2026-11-24
- 상태: 2026-11-23~24, 2026-11-27 사용자 결정 반영
- 근거 문서: [기능정의서](03-feature-spec.md), [정보구조도(IA)](02-information-architecture.md), [설계 문서](../superpowers/specs/2026-11-18-account-book-design.md)
- 표기: `[사용자]` 사용자가 직접 정함(괄호는 정한 날), `~` 시간이 남을 때만 한다(1절). 기능 ID, 기능 이름, 단계 표시 `[1]`은 기능정의서를, 화면 ID는 IA를 따른다.

## 1. 왜 나누는가

- 1단계 기능은 76개다. 한 묶음으로 두면 끝이 보이지 않아서, 기간을 먼저 정하고 그 안에 들어오게 범위를 맞춘다. `[사용자]`(2026-11-23)
- 1단계에 쓰는 시간은 6주이고 세 조각으로 나눈다: 1A 3주, 1B 2주, 1C 1주.
- 조각의 기간이 끝났는데 안 된 것이 있으면 기간을 늘리지 않는다. `~` 표시 항목부터 다음으로 넘기고, 꼭 필요한 것이 안 풀렸으면 설계로 돌려보낸다.
- 진척은 기능 개수가 아니라 "이 조각으로 실제로 무엇을 할 수 있게 됐나"로 본다.
- `~` 표시는 "시간이 남을 때만 한다"는 뜻이다. 기준은 혼자 쓰는 핵심 사용자가 매주 겪는가이다.
- 날짜는 추정이고 약속이 아니다. 1A는 2026-11-30 시작을 가정한다.

## 2. 조각 요약

| 조각 | 기간 | 끝났을 때 되는 일 | 풀려는 막힘 |
|------|------|------------------|-------------|
| 1A 매일 적는다 | 3주 | 아이폰 홈 화면과 맥에서 로그인해 지출을 적고, 이번 달 합계와 계좌 잔액을 본다 | 맥에서 적은 것이 아이폰에 안 보인다 |
| 1B 빨리 적고 안 잃는다 | 2주 | 달력에서 날짜별 합계를 한눈에 보고, "점심 12000" 한 줄로 적고, 연결이 없을 때 적은 것이 나중에 올라가고, 엑셀로 꺼낼 수 있다 | 적기 귀찮아서 미룬다, 연결이 끊기면 못 적는다 |
| 1C 찾아보고 정리한다 | 1주 | 필터와 검색으로 찾고, 잘못 넣은 것을 되돌리고, 계좌와 카테고리를 정리한다 | 지난달 그 지출을 못 찾겠다, 실수로 지웠다 |

1A에서의 범위는 다음과 같다.

- 로그아웃(F-016)은 더보기에 줄 하나로 둔다(프로필 화면 M-02는 1C).
- 카테고리 목록(F-509)은 보기만 한다.
- 넓은 화면의 목록과 상세 두 칸 배치는 1B다. 홈의 두 칸은 1A에 있다. `[사용자]`(2026-11-24)
- 거래 삭제(F-227) 직후의 "되돌리기"는 1A에 있다(휴지통 화면에서의 복원 F-230은 1C).

1A의 끝과 첫 배포는 다음과 같다.

- 1A가 끝나면 사용자가 실제 지출을 매일 적기 시작한다. 그 전에 매일 자동 백업(F-910)이 돌고 복구를 한 번 해 본다.
- 첫 배포는 1A의 로그인과 거래 만들기가 머지된 직후에 한다. `[사용자]`(2026-11-24) 그때 iPhone 홈 화면 웹앱의 입력 속도를 잰다(설계 문서 10.1).
- 1A 종료 기준은 `docs/qa/1a-exit-criteria.md`에 있다(qa 초안 8개 그대로). `[사용자]`(2026-11-24) 이 문서에는 옮겨 적지 않는다.

## 4. 1B 빨리 적고 안 잃는다 (17개)

1A가 끝에서 끝까지 동작할 때까지 서버는 1A 핵심 API를 로그인, 가입, 내 정보, refresh와 로그아웃, 계좌 목록과 추가, 카테고리 목록, 거래 만들기, 목록과 상세, 수정, 삭제와 복원 순서로 먼저 만들고, 강화 작업(1A 핵심 API를 막지 않는 DB 제약, 검증 강화, 성능 측정, 문서 정리)은 1A 뒤로 미룬다. 달력(F-222)은 1A 핵심 API가 끝나면 1B 맨 앞에서 시작한다. `[사용자]`(2026-11-27)

## 8. 기능이 아닌 일

Spring Boot 이전, 구조 결정 기록, 보안 정비, CI, 배포와 백업 스크립트처럼 기능 ID가 없는 일도 조각 기간 안에 한다. 어느 조각인지는 각 GitHub 이슈의 마일스톤(1A, 1B, 1C, 2단계)이 기준이며, 이 문서는 이슈 번호를 적지 않는다(번호가 바뀌면 문서가 낡기 때문이다).
