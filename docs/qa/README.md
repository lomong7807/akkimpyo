## 조각과 수용 기준의 기준

- 조각 구분(1A, 1B, 1C)은 GitHub 이슈 본문의 "조각" 칸이 기준이다.
- 수용 기준은 각 이슈의 "수용 기준"과 기능정의서(`docs/planning/03-feature-spec.md`)의 F-ID, P-ID를 따른다.

## 결정 기록 (owner, 2026-11-24)

1. Playwright를 도입한다. 위치는 레포 루트의 `e2e/`이고 Chromium과 WebKit으로 돌린다. CLAUDE.md에 이 위치를 한 줄 추가하는 것도 그 PR에 넣는다. 화면이 생긴 뒤에 시작한다.
2. 아이폰 실기기 확인은 첫 배포(1A의 로그인과 거래 만들기가 머지된 직후)에 생기는 주소로 한다. 그 전에는 WebKit으로 확인한다. 임시 터널은 쓰지 않는다.
3. 테스트용 가입은 테스트 환경에서만 허용 목록에 테스트용 도메인을 넣는 방식으로 한다.
4. 1A 종료 기준은 8개 그대로다.
5. 1A 권한 검증은 소유자와 구성원 아님만 한다. 구성원(편집 가능)과 보기 전용은 2단계에서 본다.
6. 시계 주입은 이슈 #5에 포함한다.
7. 테스트 전략 문서는 `docs/qa/`에 둔다.
