# 1A 종료 기준

기준: main `9a31116`(2026-11-23). 작성: qa 봇.

1A의 의도(planner): "아이폰 홈 화면과 맥에서 로그인해 지출을 적고, 이번 달 합계와 계좌 잔액을 본다." 1A가 끝나면 owner가 실제 지출을 매일 적기 시작한다.

아래 8개를 모두 채우면 1A가 끝난 것으로 본다(owner 결정 2026-11-24).

1. 1A 서버 이슈의 수용 기준 항목마다 대응하는 테스트가 있고, qa가 기대값을 바꿔 실패하는지 표본으로 확인했다.
2. 끝에서 끝까지 테스트([test-strategy.md](test-strategy.md) 3절의 4개)가 Chromium과 WebKit에서 통과한다.
3. owner 아이폰(홈 화면 설치)과 맥에서 로그인 → 지출 입력 → 이번 달 합계와 잔액 확인이 된다. 손으로 계산한 값과 일치한다.
4. 경계값 표([test-strategy.md](test-strategy.md) 4절)의 금액·날짜 항목이 API와 화면 양쪽에서 명세대로 저장되거나 거부된다.
5. 다른 사용자의 장부는 주소를 직접 열어도 404다(API와 화면).
6. 백업이 하루 한 번 돌고, 복구를 한 번 해서 거래 건수와 잔액이 같은지 확인했다.
7. 열린 S1·S2 버그가 0건이다. S3 이하는 목록으로 남기고 owner가 넘길지 정한다.
8. qa 탐색 세션 3회(입력과 합계, 인증과 토큰 만료, 아이폰 화면)의 기록이 있다.

## 판정 규칙

- 기간이 끝났는데 채우지 못하면 기간을 늘리지 않고 범위를 줄인다(planner 규칙). 무엇을 뺄지는 owner가 정한다.
- 판정은 "확인", "추정", "미확인"으로 구분해 적는다. "미확인"인 항목은 채운 것으로 치지 않는다.

## 1A에 들어가는 이슈

1A에 들어가는 이슈는 이슈 본문의 "조각" 칸이 1A인 이슈다. 번호를 이 문서에 적지 않는다(번호와 조각이 바뀌면 문서가 낡는다). 조각별 기능 범위는 planner의 조각 문서(docs/planning/03a-phase1-slices.md, 준비 중)가 기준이고, 기능 ID가 없는 일(프레임워크 이전, ADR, 보안 정비)은 이슈 본문의 조각 칸이 기준이다.
