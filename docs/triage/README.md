# 이슈 분류 기준

- 상태: owner 승인 2026-11-24
- 관리: triage 봇
- 바꾸려면 PR로 올린다.

## 1. 분류 순서

1. 칸 확인: 기대 동작, 실제 동작, 재현 방법이 있는지 본다.
2. 재현
3. 중복 찾기
4. 심각도
5. 우선순위
6. 영역과 담당 봇
7. 넘기기

이슈마다 세 가지를 적는다.

- 할 것인가
- 얼마나 중요한가
- 누가 맡는가

`gh issue create`로 만든 이슈는 양식의 필수 칸 검사를 거치지 않는다. 그래서 triage가 분류할 때 칸을 확인한다.

## 2. 심각도 (사용자 영향)

| 라벨 | 이름 | 기준 |
|------|------|------|
| S1 | 치명 | 금액·잔액이 틀리게 저장된다. 데이터 손실. 남의 장부 노출. 아무도 로그인 못 한다. 개인신용정보가 저장된다. |
| S2 | 높음 | 핵심 흐름(가입, 로그인, 거래 입력, 목록, 잔액)이 막히거나 틀린 값이 보이고 우회가 없다. |
| S3 | 보통 | 우회가 있거나 부가 기능의 고장이다. |
| S4 | 낮음 | 문구·보기 문제다. |

판정할 때 아래를 같이 적는다. 숫자 하나로 정하지 않는다.

- 영향 범위
- 저장값이 틀린지, 표시만 틀린지
- 우회 여부

## 3. 우선순위 (급한 정도)

| 라벨 | 기준 |
|------|------|
| P0 | 하던 일을 멈추고 지금 한다. main 빌드가 깨져 모두 막혔거나, 운영 데이터 손실·유출이 진행 중일 때다. |
| P1 | 지금 조각 안에 한다. 기준은 "이 문제가 있는 채로 내보내면 누군가 나쁘게 느끼는가"이다. |
| P2 | 다음 조각이 끝나기 전에 한다. |
| P3 | 기한 없음. |

심각도와 우선순위는 따로 적는다.

## 4. 보안 이슈

security의 위험도 판정(본문)을 그대로 둔다. S 라벨만 대응시켜 붙인다.

| security 판정 | S 라벨 |
|---------------|--------|
| 높음 | S2 |
| 중간 | S3 |
| 낮음·참고 | S4 |

- 치명이 나오면 owner에게 바로 올리고 S1로 본다.
- 판정이 바뀌면 security가 본문을 고치고 알린다.

## 9. 움직임 없음 기한

- needs-info: 7일 무응답이면 다시 묻는다. 14일이면 닫기를 제안한다. 합의한 뒤에만 닫는다.
- in-progress 7일, P1 3일, P0 1일 움직임이 없으면 담당 봇에게 묻는다.

## 10. triage가 하는 것과 하지 않는 것

한다.

- 라벨 붙이기
- 중복 닫기
- 정보 요청 댓글

하지 않는다.

- 수용 기준 수정
- ready 라벨
- 코드 수정

## 11. 원인 유형

원인 분석 보고에만 적는다. 라벨은 아직 만들지 않는다.

- 명세 빈칸
- 입력 검증
- 날짜·월 경계
- 동시성
- 권한
- 마이그레이션
- 설정·환경
- 의존성
- 테스트 빈칸

## 12. 원인 분석 보고 양식

버그 이슈의 댓글로 쓴다. 아래 순서로 적는다.

1. 판정: 재현됨 / 재현 안 됨 / 중복 / 버그 아님. 근거를 같이 적는다.
2. 가장 작은 재현: 커밋, 명령 또는 요청, 데이터, 돌린 횟수와 결과.
3. 범위를 좁힌 과정: 가설, 한 가지 바꾼 것, 관찰. 버린 가설도 적는다.
4. 처음 망가진 커밋: REGRESSION일 때 git bisect 결과.
5. 영향을 준 요인들: 요인마다 증거와 확인/추정/미확인.
6. 뚫린 방어: 테스트, 검증, 리뷰, 명세 중 어디서 왜 못 잡았나.
7. 영향 범위
8. 심각도·우선순위·영역·담당 봇
9. 원인 유형
10. 넘기는 것. 고치는 방법은 적지 않는다.

## 13. 회고 양식

사고 뒤에 쓴다. 비난 없이 쓴다. 파일은 `docs/postmortem/YYYY-MM-DD-제목.md`에 둔다.

- 요약
- 영향: 수치와 출처.
- 시간 순서: Asia/Seoul 기준. "어떻게 그 상태가 될 수 있었나"로 쓴다.
- 영향을 준 요인들: 하나로 줄이지 않는다. 요인마다 어떤 방어가 어떻게 뚫렸는지 적는다.
- 잘 된 것과 운이 좋았던 것
- 재발 방지: 막기, 알아채기, 대응으로 나눈다. 항목마다 이슈 번호와 담당 봇을 적는다.
- 아직 모르는 것

사람이나 봇 이름을 원인으로 적지 않는다.
