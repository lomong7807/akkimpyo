# 회고 양식 (비난 없이)

## 언제 쓰나

아래 가운데 하나라도 있으면 쓴다.

- 사용자에게 영향이 간 중단
- 데이터 손실
- 되돌리기(배포를 이전 이미지로 되돌림, 백업에서 복원)

## 규칙

- 파일은 `docs/postmortem/YYYY-MM-DD-제목.md`에 둔다([분류 기준](../triage/README.md) 13절).
- 사람이나 봇 이름을 원인으로 적지 않는다. "누가 잘못했나"가 아니라 "어떻게 그 상태가 될 수 있었나"를 쓴다.
- 직접 본 것은 "확인", 미루어 생각한 것은 "추정", 보지 못한 것은 "미확인"으로 적는다.
- 시각은 KST(Asia/Seoul)다.
- 비밀값, 토큰, 서버 주소, 이메일, 실제 거래 내역은 적지 않는다.

## 양식

아래를 복사해 쓴다.

```markdown
# YYYY-MM-DD 제목

- 종류: 중단 / 데이터 손실 / 되돌리기
- 심각도: S1 / S2 / S3 / S4
- 관련 이슈와 PR:

## 요약

두세 문장. 무슨 일이 있었고, 어떤 영향이 있었고, 지금은 어떤가.

## 영향

- 기간(KST):
- 누가 무엇을 못 했나:
- 데이터: 잃은 것, 틀리게 저장된 것, 또는 없음
- 숫자와 출처:

## 시간표 (KST)

| 시각 | 있었던 일 | 근거 |
|---|---|---|
|  | 시작 |  |
|  | 알아챔(어떻게) |  |
|  | 조치 |  |
|  | 복구 확인 |  |

## 원인

하나로 줄이지 않는다.

| 영향을 준 요인 | 뚫린 방어(테스트, 검증, 리뷰, 명세, 알림) | 확인 / 추정 / 미확인과 근거 |
|---|---|---|
|  |  |  |

## 잘된 것과 운이 좋았던 것

- 잘된 것:
- 운이 좋았던 것:

| 할 일 | 종류(막기 / 알아채기 / 대응) | 담당 | 기한 | 이슈 |
|---|---|---|---|---|
|  |  |  |  | # |

## 아직 모르는 것
```
